# Application structure and shared results

`dist/app.js` owns boot, the current draft/catalogue, transient browsing state, event wiring and shell composition. Feature factories in `dist/features/` own shared controls, Origins, creation views, Experience, shop, review, dialogs, creation resets, actions and the workspace shell. Factories receive a live context; assigning a replaced draft/catalogue or UI preference immediately publishes it through the explicit state setter. Book mechanics remain named handlers in the supplement modules. No book JSON executes code.

Startup fetches the compact generated `data/book-library.json` through `book-bundle.mjs`, which checks format, manifests, declared data keys, core identity, aliases and the dependency graph. It does not assemble disabled books. `assembleBooks` still validates the selected catalogue, and `catalogForCharacter` still checks current save selections/versions and character state. Build/test tooling uses the full `loadBookLibrary` source loader, including coverage, alias targets and every installed pack's dependency-context catalogue validation. `generate-books.mjs` writes the bundle only after that full validation; `check:generated` detects any difference from the current sources. The bundle contains the same rule data except standalone reference prose: `ruleReferences` retain identity/category/topic/page/target/aliases plus a generated `textRef: true` pointer. `rule-references.mjs` can hydrate source prose from `data/rule-reference-library.json` with version/identity checks. UI search instead lazily fetches the common generated `data/search-library.json`, independently of character selections. Switching books needs no additional character-rule fetch and changes no calculated behavior. Only the full build/test loader accepts original source prose; generated pointers never belong in source packs. The offline worker includes both the bundle and the individual source assets, trading a small additional cache copy for a single startup request.

`character-result.mjs` produces the common derived scores, load/equipment result, purse, effective Career, Skill rows, known magic/runes/techniques/Cants, compact gear summaries and issues. Equipment summary formatting lives in `folio-gear.mjs` to keep the calculation layer independent of the folio renderer. The app caches one snapshot per serialized draft revision and catalogue identity. In-place changes, undo and book switches invalidate it. Folio and review consume the same Skill rows; both PDF exports receive this same result, and the appended record reuses the sheet's result. Independent export callers can omit the result and calculate once. Eligibility/price quote handlers remain explicit rules; they are not replaced by presentation calculations.

Issues carry `{code, message, severity, source, control: {step, target}}`. Rule validators create codes and destinations where failures are detected; routing never reads message wording. Warnings and information do not block purchases/export. String-returning rule APIs remain for existing integrations/tests; the application requests structured records. Do not add a message-regex routing fallback. Correct a target at its rule source, keeping it in sync with the actual control. Book/page metadata drives source buttons; displayed source labels are never parsed to discover their destinations.

`content-references.mjs` contains reviewed exact aliases with their kind, source, scope and decision. `resolveContent` accepts an active `contentId` or an unambiguous scoped name and rejects ambiguity/unavailable content. A name does not select between Career variants. No fuzzy mapping or general Fourth Edition conversion is permitted. Existing equipment bundle parsing, contextual Ogre sizing and unusual book mechanics remain explicit handlers.

Expandable sections use `data-detail-key`, composed by `detailKey(section, entry)`. Content IDs are preferred; otherwise use an explicit stable key/name in that section. Capture/restore uses this key only, never a summary's English text. Repeated sections must include content identity; don't use positional row numbers or a translated label as identity.

`book-search.mjs` projects a validated catalogue into explicit source fields, supported specialisations and exact scoped aliases. `search-library.mjs` builds the common all-book corpus at build time, reading each pack in its own dependency context and deduplicating stable identities. Separate Career variants and withdrawn source profiles remain readable references; they never override character creation. The compact asset shares identical profiles and derives normalised strings after lazy loading. `search-metadata.mjs` adds explicit source-derived filter values at build time; `search-filters.mjs` owns category grouping, the shared filter schema and matching. Wire schema 2 validates those values without changing printed record identities or search text. `reference-search.mjs` and `reference-body.mjs` provide identical source/Legacy reading panes, safe profile rendering, chaining and history in both creators. `features/book-search.mjs` and `gm/references.mjs` are thin wrappers. `search-controller.mjs` owns the persistent field, native category/book/category-specific filters and chips, 20-result batches/IntersectionObserver, loading/retry, keyboard controls and the desktop/mobile modal. It mounts the same input rather than cloning it, preserving query/filter/list position on return. Desktop shows results beside its reading pane; mobile switches views. Search is immutable reference state: changing character books does not invalidate it, and there are no creator actions or navigation routes in the dialog. `search-presentation.mjs` supplies category labels, escaped prose/tables and DOM linking; `book-search-links.mjs` resolves exact related names with same-source preference or explicit ambiguity. Standalone NPC/creature profiles and templates are filtered out at build time by the shared reference-category policy; loading rejects them if a stale asset reintroduces them. No NPC reader targets enter chaining. Their reviewed source records and the independent GM catalogue remain intact. See [BOOK-SEARCH.md](BOOK-SEARCH.md).

The registry loads each book's reviewed `coverage.json`. Generated source inventories include profiles even if combined-book precedence withdraws them. Active catalogue counts apply those precedence decisions. Catalog records and chapter/features have separate counts; supporting a learnable spell profile does not claim live spellcasting automation. Details and maintenance commands are in [BOOKS.md](BOOKS.md) and [INCLUSION-MATRIX.md](INCLUSION-MATRIX.md).

## Shared presentation system

`design-tokens.css` and `design-system.css` load after feature styles and own the Black Banner visual contract. `design-system.mjs` provides safe, accessible page-heading and emblem markup. Creation views and book setup use its common heading, while the shell uses the common emblem. Motion follows the OS preference through CSS. `install-control.mjs` keeps the same browser-owned Install app button when mounting it into each new rail, preserving PWA listeners and state across redraws; `pwa.mjs` continues to own install/update behavior. Fonts/art/icons and the standalone component guide are included by the recursive offline build. Future features use shared roles/controls instead of copying visual preview code; see [DESIGN-SYSTEM.md](DESIGN-SYSTEM.md).

GM PDF exports share `gm/pdf-text.mjs` for mixed-weight wrapping and drawing. Card labels use bold type while values remain regular; fit measurement uses the exact font faces that render the PDF. Full stat blocks use the same helper for attack, magic, Corruption and personality labels.

## Player creation scope

The separate GM workshop with core and opt-in reviewed Up in Arms/Archives I/Archives II/Archives III content is a separate entry point (`gm.html`) with modules under `dist/gm/`. It does not restore the removed runtime or add GM imports to PC startup. `creator-switch.mjs` is the only shared navigation dependency. Reviewed source extraction is compiled during `generate-books.mjs`, with a content fingerprint, into `gm/data.json` and a separate generated inventory. `model.mjs` validates independent saves and calculates a single result; views, folio, review, compact PDF and A4 table cards consume it. `printing.mjs` owns a temporary local print batch; `print.mjs` measures and renders six/four cards per page, blocking overflow at the minimum readable font size. Issues use the same structured severity/source/control contract. Text editing refreshes result surfaces without replacing the active input or swallowing a subsequent click. `books.mjs` validates independent GM book selections and caches each selected rules catalogue. The compiler checks each GM source checksum against its owning installed pack; PC manifests do not acquire GM collections. Imported print drafts resolve their own book selections, so mixed-book batches calculate consistently. `cants.mjs` owns GM Cant calculation, validation and pruning; `cant-controls.mjs` owns compact spell Lore/Cant fields. Schema-2 GM drafts store independent `spellLores` and `cants`. Calculated selections are shared by folio, review and both exports. Career development, hirelings and XP are excluded. See [GM-WORKSHOP.md](GM-WORKSHOP.md).

`talent-targets.mjs` validates explicit player Causes and Career eligibility; `talent-targets-ui.mjs` provides the choice control. `deft-steps.mjs` attaches reviewed Miracle replacements to their aspect lists without modifying global core definitions. `career-variants.mjs` supports mutually exclusive Career profiles and preserves the Species/identity reset boundary.

## Printed gameplay reference imports

`reference-entries.mjs` validates unconverted printed text independently of creator schemas. Its `referenceEntries` registry file is not assembled into character/GM options. Each record owns its source, stable identity, category, topic and page; separate notes cannot enter matching. The reader safely renders source Markdown without stripping genuine printed words. Fourth Edition text receives an edition warning; selective Legacy metadata continues to describe actual approved adaptations on existing profiles.

`search-ranking.mjs` owns pure normalisation/ranking. `search-engine.mjs` constructs a module worker on first search, sends only searchable projections and maps ranked keys back to source profiles. `search-worker.mjs` performs normalisation/ranking off the main thread. Per-request replies and controller generations reject stale results; worker startup/runtime errors or timeouts fall back to the same synchronous matcher. Character state never enters worker messages. Full text remains outside the startup bundle, and compact printed records avoid duplicate textFields copies.

`search-coverage.mjs` is build-only. It checks the frozen source review against installed pack hashes, count/target identities and published reference-file hashes, then generates a separate search coverage report. Creator inclusion statuses continue to describe automation. Extraction helpers stage source data outside the app; they cannot publish unreviewed chunks.

Search coverage audits retained sources separately from active results. `search-coverage.mjs` accepts excluded targets only when their exact identities exist in retained profile/template data or the compiled GM catalogue; arbitrary missing targets still fail. Generated inclusion records mark retained supplemental NPC references deferred. No full stat blocks are shipped in the lazy search corpus.

The Rules cleanup removes explicitly reviewed non-mechanical records from published source collections, rather than filtering prose by keywords at runtime. The frozen per-book `rulesAudit` records excluded identities, names, pages and reasons, and the reviewed prior Rules count. Coverage generation rejects a restored identity in either raw sources or the corpus, and rejects stale audit totals. It publishes the exclusion list alongside current counts. Adding a legitimate Rule requires updating the reviewed baseline, while preserving excluded identities.

## Local browser regression boundary

`playwright.config.mjs`, `scripts/run-browser-tests.mjs`, `scripts/browser-test-server.mjs` and `tests/browser/` are development-only. The runner caches successful preparation using `scripts/browser-build.mjs`, which hashes inputs and published outputs. A test-owned static server serves only `dist`; fresh contexts isolate verification drafts and worker caches. Focused tagged suites check both creator entry points through their real controls and downloaded files. PWA tests exercise offline/update flows with real workers; a cookie changes only the test server's worker version for the update scenario. No runtime test hooks, hosted CI or deployment changes are introduced. See [TESTING.md](TESTING.md) for commands and release policy.
