## Reproduction details and recommended corrections

### QA-01 — Persistent mobile balances are hidden

**Reproduce:** Open a completed Player draft at 390px. Go to Experience and scroll to purchases, or open Gear and scroll to the shop.

**Observed:** The fixed bar contains View character and Undo/Redo, but no XP or remaining coin. The DOM still contains, for example, `1,000 XP · 5/11`; its computed display is `none`. A user must return to a budget summary or leave the current choice to open the folio. This contradicts the documented persistent XP/coin strip and makes repeated purchases harder to monitor. The same absence is visible in the 768px capture.

**Expected:** Keep compact, current balances visible while users browse and buy.

**Recommendation:** Reflow the mobile bar, or provide a compact second line, retaining the existing 44px history and folio controls.

**Location:** [react-shell.css:37](C:/Users/ninod/Documents/ChatGPT/warhammer/character-generator/src/styles/react-shell.css:37). The balance is authored in [workspace-shell.mjs:650](C:/Users/ninod/Documents/ChatGPT/warhammer/character-generator/src/features/player/presentation/features/workspace-shell.mjs:650).

**Evidence:** [Experience at 390px](C:/Users/ninod/Documents/ChatGPT/warhammer/character-generator/test-results/qa-2026-10-19/player-390-experience.png).

### QA-02 — Long Review names lose their visual first letter

**Reproduce:** Set the name to `Siegfried Maximilian von Drachenfels-Wiśniewska-Kowalczyk`. Open Player Review at 320px; the defect is also visible on desktop when the heading wraps.

**Observed:** The decorated `S` is vertically centred beside the entire multiline name. The first line appears to start with `iegfried`, while the `S` sits beside a later line. The accessible heading still contains the full name, so this is a visual rendering defect rather than stored-name corruption.

**Expected:** Read the complete name in its normal order, with decoration attached to the first line.

**Recommendation:** Use a normal full-name heading for character identity, or align the initial to the first text line. Preserve the selected decorative treatment on short chapter titles.

**Location:** [design-system.css:57](C:/Users/ninod/Documents/ChatGPT/warhammer/character-generator/src/styles/design-system.css:57), [review-sheet.mjs:293](C:/Users/ninod/Documents/ChatGPT/warhammer/character-generator/src/features/player/presentation/review-sheet.mjs:293).

**Evidence:** [320px](C:/Users/ninod/Documents/ChatGPT/warhammer/character-generator/test-results/qa-2026-10-19/player-320-review.png), [desktop](C:/Users/ninod/Documents/ChatGPT/warhammer/character-generator/test-results/qa-2026-10-19/player-1440-review.png).

### QA-03 — Bestiary numerical inputs clip when text grows

**Reproduce:** Choose Griffon, open Customise → Characteristics at 1440px, and set the root font size to 200% using the supplied enlarged-text probe.

**Observed:** Two-digit values such as 50, 45 and 60 are squeezed against/cut by the right input edge. Eight inputs measured 62px of scrollable content in a 58px client width. The whole page still fits, which is why a document-overflow test misses the defect.

**Expected:** The complete editable number remains readable when text is enlarged.

**Recommendation:** Size numerical fields in character units with padding and native spinner space accounted for, and allow row wrapping at narrow container widths.

**Location:** [gm/style.css:300](C:/Users/ninod/Documents/ChatGPT/warhammer/character-generator/src/styles/gm/style.css:300).

**Evidence:** [enlarged desktop text](C:/Users/ninod/Documents/ChatGPT/warhammer/character-generator/test-results/qa-2026-10-19/gm-1440-text200.png), [measurements](C:/Users/ninod/Documents/ChatGPT/warhammer/character-generator/test-results/qa-2026-10-19/enlarged.json).

### QA-04 — Interactive source buttons inside interactive summaries

**Reproduce:** Inspect Origins → Random creation bonuses, Talents → Warrior Born / Your Dooming, or the Talent list in Review. Tab through the disclosure and source controls.

**Observed:** A focusable source button is a descendant of a native `<summary>`, which is itself a disclosure control. Axe reports one instance in Origins, two in the tested Talents screen and six in Review, on both desktop and phone. This structure can cause inconsistent announcements and focus behavior across assistive technologies. A physical screen-reader session was not performed, so no particular reader's failure is claimed.

**Expected:** Disclosure and source-reference actions remain separate, clearly named controls.

**Recommendation:** Place the source action beside the disclosure, or inside its expanded content. Preserve mouse/touch source access and the current compact presentation.

**Location:** [origins-view.mjs:278](C:/Users/ninod/Documents/ChatGPT/warhammer/character-generator/src/features/player/presentation/features/origins-view.mjs:278), [creation-views.mjs:1179](C:/Users/ninod/Documents/ChatGPT/warhammer/character-generator/src/features/player/presentation/features/creation-views.mjs:1179), [controls.mjs:159](C:/Users/ninod/Documents/ChatGPT/warhammer/character-generator/src/features/player/presentation/features/controls.mjs:159).

**Evidence:** `nested-interactive` nodes in the accessibility results, including the exact rendered HTML and selectors.

### QA-05 — Player book cards overstate what selecting a book adds

**Reproduce:** In Player, open Choose books and inspect The Warband of Bayl of Many Eyes.

**Observed:** It is labelled “Additional character options” with the fallback “Optional rules and source references.” Its Player pack contains coverage/reference metadata, with zero published reference entries and no additional Player Species, Careers, Skills, Talents, spells or equipment. Assembling Core plus Bayl leaves all ten tested PC catalogue counts identical to Core. Shared reference search is available independently of selected character books. The card does not explain its actual GM-focused scope, while the surrounding notice warns that changing books starts a new character.

**Expected:** A user can identify the concrete effect of selecting a book before accepting a character reset.

**Recommendation:** Generate role-specific contribution copy from the registered data. Clearly label books without selectable PC additions, or omit their nonfunctional selection from Player. Do not remove the books or their options from Bestiary.

**Location:** [book-ui.mjs:93](C:/Users/ninod/Documents/ChatGPT/warhammer/character-generator/src/features/player/presentation/book-ui.mjs:93), [workspace.mjs:20](C:/Users/ninod/Documents/ChatGPT/warhammer/character-generator/src/engine/workspace.mjs:20).

**Evidence:** [Player book chooser](C:/Users/ninod/Documents/ChatGPT/warhammer/character-generator/test-results/qa-2026-10-19/player-book-chooser.png) and the `bayl-many-eyes` manifest/data in the generated book library. This is a scope/decision-support defect, not a request to change game rules.

### QA-06 — Marijan's mobile filter row crops its essential controls

**Reproduce:** At 320–390px, scroll to Marijan Skills, Talents or another add-entry section.

**Observed:** Search, the fixed 90px Book selector and + Custom share one row. Even the default “All books” label is visibly cut; long source selections are harder to identify. At 320px, search collapses to approximately “Find by n…”. Expanded custom Skill names themselves remain readable, so this finding concerns the filter bar, not the fixed long-name behavior.

**Expected:** The current source filter and the search field remain legible.

**Recommendation:** Put search across the full row, with Book and + Custom below it. Alternatively expose the full selected book label beneath the control.

**Location:** [marijan/style.css:763](C:/Users/ninod/Documents/ChatGPT/warhammer/character-generator/src/styles/marijan/style.css:763).

## Additional verification notes

**Contrast requires follow-up:** One Bestiary scan flagged the fourth navigation number at 3.42:1 (`#ab9768` over the reported `#304560`), below the tool's 4.5:1 threshold for its 14px normal text. The sidebar uses a textured surface, and the finding did not appear across every scan. It is retained in raw results for a dedicated background/state contrast check, not counted as an independently confirmed uniform contrast defect. Many other textured-background comparisons were inconclusive, so this report does not claim full contrast compliance.

**What held up:** No horizontal page overflow was measured in the 105 populated captures. Search results/readers had no axe violations in the four scanned desktop/phone states. Player and Bestiary tabs responded to arrow-key navigation and moved focus to the selected tab. Marijan's expanded long custom Skill names wrapped readably; the tested inputs had labels and no duplicate IDs. Unicode labels rendered without replacement glyphs. The previous review's reported numeric Advance clipping and missing full custom Skill names were not reintroduced in the tested normal-text states.

**Limits:** No physical phone, software keyboard, notch/safe-area hardware, native OS picker, real screen-reader session or full Firefox run was verified. No exhaustive rulebook correctness review, security audit, performance certification or visual inspection of every possible export was performed. Fixed approved themes were tested; an unsupported RTL/theme switch was not invented for this audit.
