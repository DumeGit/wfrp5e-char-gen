# Search the books

The Black Banner masthead has a centred desktop search field and compact dropdown. On phones, its launcher opens a full-screen **Search the books** panel, with the same input and a native category selector above one scrolling result list. References open in a separate dialog. Existing Career, Experience, magic and shop filters remain independent.

## Categories and results

**All categories** is the default. The optional native selector offers only categories present in the current index: Rules, Conditions, Psychology, Qualities & Flaws, Creature Traits, Species & Origins, Careers, Skills, Talents, Magic and Equipment. Both creators also offer Creatures, Templates and Corruption. Choosing a category without entering text browses its references alphabetically; an empty All categories query shows a hint.

Exact names, scoped reviewed aliases, prefixes and other name matches precede description/metadata matches. Words can match in different parts of a profile. Normalisation ignores case, punctuation and accents; it never invents a rule equivalent. Each result shows name, category/topic, book/page, a matching excerpt where available and selective Legacy status. Printed worked examples are labelled in their topic. Same-name rules remain distinct: Psychology Fear and the Creature Trait are separate references, as are Item and Weapon properties.

Results append in batches of 20 when the list approaches its end. An accessible **Load more results** button provides a fallback, and the final batch shows an end message. Query/category changes reset the list; appending preserves existing rows and scroll. No input node is replaced or cloned. Arrow keys choose results, Enter opens a reference, Escape closes search, and Clear empties the query. Keyboard composition is respected. The field stays disabled until startup has installed its handlers, so typing cannot be lost during initial loading. Clicking the field, icon or padding focuses it once; result clicks cannot be swallowed by a blur-driven redraw.

**Back to search** restores query, category, loaded batch count and list position. Closing a reference dismisses results and returns focus without reopening them. Search state is transient and excluded from character/GM saves and exports. Changing enabled creation books does not change the reference library or erase search history.

## Scope and sources

PC and GM search use the **same complete imported reference library**, independent of enabled character books and the screen being viewed. This is imported content, not full PDF text. It includes Careers and their levels, Skills and supported specialisations, Talents/options, spells/prayers/rituals, runes, techniques, Cants, equipment, Species/origins and reviewed core profiles/templates/Corruption. Generation reads each pack in its own dependency context and deduplicates stable identities, retaining separate source variants and older withdrawn profiles as references. Creation continues to enforce its selected-book precedence, withdrawals and eligibility. Exact same-name equipment facets within a source book are joined. Documented scoped aliases are collected from their validated pack contexts. Unavailable entries remain readable without acquiring new prices, choices or eligibility.

The supplied Fifth Edition core adds **435 source records**: 45 Skill descriptions, 13 Conditions, five Psychology rules, 36 equipment Qualities/Flaws, 67 Creature Traits and 269 selected rules. Skill descriptions enrich existing canonical Skill/specialisation rows rather than duplicate them. Rule topics cover Tests, Fate/Fortune, social interaction/investigation, travel/crafting, combat, health, Corruption, advancement, prayers, magic, equipment and Bestiary customisation. Common tables include Test Difficulty/outcomes, Movement, Hit Locations, combat modifiers, Oops!/Misfires, advancement costs including Appendix II +1 purchases, Overcasting, Availability and Encumbrance. Tables preserve printed values, including the repeated +45 Skill price. Advance-scheme symbols are described in words where the text extraction cannot convey the icons.

These are selected page-addressed references, **not an exhaustive search of every core chapter or every table**. Full critical-injury, miscast, campaign/downtime tables and lore chapters are not newly imported by this change. Standalone supplement rule chapters beyond existing imports remain deferred. Imported supplement options are searchable in both creators even when their creation books are disabled. Source-warning commentary is excluded from matching. Reading Conditions/combat rules does not add tracking, automatic rolls, spent resources or manager features.

Source data belongs in `data/books/core/rule-references.json` under the registry's `ruleReferences` file key. Each record carries stable ID, category, topic, printed page, text and optional exact aliases; a Skill description requires its canonical Skill target. No full source PDF is shipped. Raw records require prose and cannot contain generated `textRef` pointers. The inventory marks these as **reference-only**, distinguishing reading a rule from implementing its play system.

## Loading and offline use

The startup bundle contains validated reference metadata and `textRef: true`, keeping long prose out of the creator's initial request. `generate:books` writes the full, common index to `data/search-library.json`, with shared profile records and no duplicated normalised strings. First search fetches it lazily, checks installed book versions and record identities, and hydrates matching strings. It also generates `data/rule-reference-library.json` for validated source-text hydration. All dependency-context assembly happens at build time, not browser startup or first search. Shared core text and category controls do not import GM runtime into PC startup. Search shows loading/error feedback and a Retry control; stale/mismatched text is rejected rather than silently mixed with an older catalogue. Source/metadata/full-library outputs are all cached by the versioned offline worker, so first search also works after a completed offline installation.

## References and chaining

Adaptation/conversion notes and internal app decisions are **excluded from matching**. Explicit book-content fields are indexed instead of serialised records. `book-search-text.mjs` separates reviewed embedded annotations without deleting stored text, and preserves genuine book words such as “creator”. New imports must keep commentary in separate metadata. The app's approved adapted profiles remain searchable; original Fourth Edition reconstruction was not requested. Actual adaptations keep selective Legacy badges/explanations. Core source rules remain unchanged references even when the creator uses a user-approved convention, such as ignoring coin weight.

Dialogs contain book references, descriptions, profile fields and source/Legacy access, with no **Use in the creator** section, ownership/status panel or appended creator commentary. Reference dialogs have no creator navigation or actions. Reading a book does not enable it or modify either draft. Actual creation controls remain authoritative.

Exact catalogue names and reviewed scoped aliases in the body become discreet links, preserving wording, word boundaries and the longest complete term. The current reference's own name and unimported terms stay plain. Same-book targets are preferred; multiple remaining targets require an explicit reference choice. Hover/focus provides a short desktop preview, click/tap opens the entry, and **Back / Previous reference** retraces the chain, including ambiguous choices. Separate source/Legacy dialogs can open above a reference in either creator and return to it. Chaining never changes a build or enables a book.

## Modules and maintenance

- `book-search.mjs`: pure index/ranking/pagination and existing PC navigation context.
- `rule-references.mjs`: source validation and lazy version/identity-checked hydration.
- `search-controller.mjs`: shared field, category, loading/retry, keyboard, result batches, mobile modal and return position.
- `search-presentation.mjs`: shared category labels, escaped paragraphs/bullets/tables, Species metadata and related-term DOM links.
- `book-search-text.mjs` / `book-search-links.mjs`: annotation separation and exact related-name/alias resolution.
- `search-library.mjs`: build-time all-pack index, compact wire format and version-checked lazy loading.
- `reference-search.mjs` / `reference-body.mjs`: common source/Legacy reader, safe profiles and chain history.
- `features/book-search.mjs` / `gm/references.mjs`: thin entry-point wrappers around the same reader.
- `book-search.css`: shared desktop/mobile surfaces using Black Banner semantic tokens.

Add a rule only after reviewing its supplied page and checking tables/symbols against the PDF. Bump the book version and regenerate all libraries, registry coverage/counts and offline assets together. Keep creator handlers separate from reference prose and do not imply exhaustive coverage. Run `npm run check:release` before committing, update affected Markdown and commit locally without pushing.

Outcome tests cover all-book availability with a core-only draft, separate source variants and withdrawn profiles, selective Legacy status, facet joins, stable identities, aliases/ranking/category browsing/pagination, full Skill prose, unchanged character calculations, source table values, safe rendering, lazy hydration and stale/malformed/failing sources. Browser checks use isolated `?verify=1` drafts for one-click focus, caret/keyboard, chained references and ambiguity, list return position, automatic/fallback batches, book-selection independence and desktop/mobile layout. Simulated phone viewports verify layout; real iOS/Android software keyboards and native picker behavior require an actual device and must not be reported as tested through desktop emulation.
