# Search the books

The masthead search launcher opens the same **Search the books** workspace in both creators. Desktop uses a large centred modal with results on the left and a reading pane on the right. Phones use a full-screen modal with separate results/reference views; **Back to search** restores the results. The input node stays stable throughout. Existing Career, Experience, magic and shop filters remain independent.

## Categories and results

**All categories** is the default and stays first; the remaining category labels are sorted alphabetically. Native selectors offer Category and **Book** in every view. Categories include Rules, Tables, Endeavours, Conditions, Psychology, Qualities & Flaws, Creature Traits, Species & Origins, Careers, Skills, Talents, **Spells, Prayers & Cants**, **Runes**, **Techniques**, **Trappings** and **Mutations**. Choosing a category or book with an empty query browses alphabetically; an empty unfiltered All categories view shows a hint.

| Category | Additional filters |
| --- | --- |
| Careers | Class; Species |
| Mutations | Physical/Mental |
| Qualities & Flaws | Quality/Flaw; Applicable to |
| Runes | Applicable to; Rune label |
| Skills | Basic/Advanced; Characteristic |
| Spells, Prayers & Cants | Type; Lore / Patron |
| Trappings | Type |

Other categories have only Book. Different filters combine with AND and with the query. All is the default for each selector. Desktop uses a compact toolbar: the query, Category and Book share one row, with inline category-specific filters beneath. Controls use the shared 36 px compact height, without shrinking the reference text. Category filters expand under **More filters** on phones, which retain 16 px text and 44 px touch controls. Active filters have removable chips and a **Clear filters** action; clearing filters preserves the category and query. Each category remembers its filters while the search workspace is open, but only the current category's filters apply. The global Book choice persists across category changes. Book offers the eleven supplied books; internal Career variant packs are grouped with their matching parent PDF, while remaining distinct readable profiles. Empty filtered results still show a clear no-matches message.

Rune labels are exactly **No label, Weapon Rune, Armour Rune, Runic Talisman, Protection Rune, Engineering Rune, Doom Rune, Master Rune**. A Master Rune also retains its printed form label, so e.g. Armour Rune includes ordinary and master Armour runes; combine Master Rune with Applicable to: Armour to narrow further. No label is available even when it currently has no matches. Applicability follows printed forms: Weapons, Armour, Talismans, Protection items, Engineering weapons and Anvil of Doom.

Spell Type distinguishes Petty spell, Arcane spell, Lore spell, Blessing, Miracle, Ritual, Cant and source entries labelled only Spell. Lore/Patron uses source traditions, explicit cult prayer lists and each Cant's Colour Lore. Its native dropdown visually separates **Lores** and **Patrons** with labelled option groups; unclassified entries sit under **Other**. The groups preserve the existing filter values and selection behavior in both creators, including mobile. Generic Arcane profiles retain Arcane rather than borrowing a Lore assigned by a character. Rune knowledge and Sword-dancing Techniques remain separate accessible categories.

Filters use generated `filterValues`, kept separate from indexed prose and immutable source entries. Class/Species comes from Career profiles and explicit source eligibility declarations, not the current character. The four printed High Elf Career references (Mage, Smith-priest of Vaul, Storm Weaver and Loremaster of Hoeth) use reviewed Academic class metadata. Origin-specific restrictions still apply in creation and remain visible in the source profile. Broad printed equipment groups stay broad (e.g. Animals & vehicles); existing shop categories supply ordinary goods types, and joined typed profiles take precedence over an unclassified shop facet. Source-only entries with no explicit value appear under **Not specified**, rather than disappearing or receiving invented metadata. General Item Qualities/Flaws also match Weapons and Armour applicability. Supplementary properties have reviewed identity-based classifications. New imports must extend metadata explicitly when needed; no runtime prose-keyword heuristic is used.

Categories describe the purpose of a reference, not whether the PDF places it in a grid. **Tables** contains roll, lookup and comparison tables. Standalone creature/NPC stat blocks retain a profile category in source data but are excluded from current search; Career advance grids belong to **Careers**; concrete game procedures, calculations, definitions, restrictions and effects belong to **Rules**; named item profiles belong to **Trappings**. A rule or item may retain a supporting table inside its dialog without being listed under Tables. Table introductions and their rows are one result, and duplicated stat blocks are consolidated into the complete reviewed profile.

Standalone NPC/creature profiles and all templates are excluded from shared search by the user’s latest 8 October decision. **NPCs & Creatures** and **Templates** do not appear in the category selector. Their entries are absent from results and reference chaining, including core profiles/templates and supplemental named NPC descriptions. Reviewed source records remain validated in their book files for possible future use; the GM creator’s own 49 core profiles and seven templates are unchanged. Up in Arms' hireling-only templates and their selection table remain deferred. General Creature Traits, Bestiary rules, Corruption, generation tables and other hireling reading/prices remain searchable.

Exact names, scoped reviewed aliases, prefixes and other name matches precede description/metadata matches. Words can match in different parts of a profile. Normalisation ignores case, punctuation and accents; it never invents a rule equivalent. Each result shows name, category/topic, book/page, a matching excerpt where available and selective Legacy status. Printed worked examples are labelled in their topic. Same-name rules remain distinct: Psychology Fear and the Creature Trait are separate references, as are Item and Weapon properties.

Results append in batches of 20 when the list approaches its end. **Load more results** is hidden when automatic loading is available; it appears only in browsers without IntersectionObserver support. Arrow-key navigation also appends batches when reaching a result beyond those already loaded. A failed reference-library request still shows its separate Retry action, and the final batch shows an end message. Query/category/filter changes reset the list; appending preserves existing rows and scroll. No input node is replaced or cloned. Arrow keys choose results, Enter opens a reference, Escape closes search, and Clear empties the query. Keyboard composition is respected. The field stays disabled until startup has installed its handlers, so typing cannot be lost during initial loading. Clicking the field, icon or padding focuses it once; result clicks cannot be swallowed by a blur-driven redraw.

Phones also provide a **Results** button above the reference, so returning does not require scrolling to its end. **Back to search** restores query, category, filters, loaded batch count and list position. Desktop references keep the results alongside them. Closing the workspace resets the query, category, Book and every remembered category filter, clears results and reference history, and returns focus to its launcher without reopening it. Reopening starts with a blank query, All categories and All books. Previous-reference history restores the reading pane scroll position. Search state is transient and excluded from character/GM saves and exports. Changing enabled creation books does not change the reference library or erase search history.

## Scope and sources

PC and GM search use the **same active reference library**, independent of enabled character books and the screen being viewed. This is imported content, not full PDF text. It includes Careers and their levels, Skills and supported specialisations, Talents/options, spells/prayers/rituals, runes, techniques, Cants, equipment, Species/origins and reviewed core Corruption. Standalone NPC/creature profiles and templates are excluded from this shared reader. Generation reads each pack in its own dependency context and deduplicates stable identities, retaining separate source variants and older withdrawn profiles as references. Creation continues to enforce its selected-book precedence, withdrawals and eligibility. Exact same-name equipment facets within a source book are joined. Documented scoped aliases are collected from their validated pack contexts. Unavailable entries remain readable without acquiring new prices, choices or eligibility.

The supplied Fifth Edition core adds **430 source records**: 45 Skill descriptions, 13 Conditions, five Psychology rules, 36 equipment Qualities/Flaws, 67 Creature Traits and 264 selected rules. Skill descriptions enrich existing canonical Skill/specialisation rows rather than duplicate them. Rule topics cover Tests, Fate/Fortune, social interaction/investigation, travel/crafting, combat, health, Corruption, advancement, prayers, magic, equipment and Bestiary customisation. Common tables include Test Difficulty/outcomes, Movement, Hit Locations, combat modifiers, Oops!/Misfires, advancement costs including Appendix II +1 purchases, Overcasting, Availability and Encumbrance. Tables preserve printed values, including the repeated +45 Skill price. Advance-scheme symbols are described in words where the text extraction cannot convey the icons.

The expanded catalogue adds printed gameplay references from all twelve books, including complete critical-injury/miscast tables, downtime, Endeavours, artifice, Enterprises, alternative armour, familiars and criminal/wilderness systems; isolated printed NPC profiles are retained in source files but excluded from search. [SEARCH-COVERAGE.md](SEARCH-COVERAGE.md) records source ranges, counts, exclusions and unresolved extraction checks separately from creator inclusion. This is a curated gameplay catalogue, **not an exhaustive search of every PDF sentence**; setting-only text, history/flavour, standalone introductions and empty cross-references, general storytelling advice, adventure scenes/plots and secrets are excluded. Qualitative requirements (including cult strictures) and worked examples of mechanics remain eligible; a rule need not contain numbers. Imported supplement options are searchable in both creators even when their creation books are disabled. Source-warning commentary is excluded from matching. Reading Conditions/combat rules does not add tracking, automatic rolls, spent resources or manager features.

Source data belongs in `data/books/core/rule-references.json` under the registry's `ruleReferences` file key. Each record carries stable ID, category, topic, printed page, text and optional exact aliases; a Skill description requires its canonical Skill target. No full source PDF is shipped. Raw records require prose and cannot contain generated `textRef` pointers. The inventory marks these as **reference-only**, distinguishing reading a rule from implementing its play system.

## Loading and offline use

The startup bundle contains validated reference metadata and `textRef: true`, keeping long prose out of the creator's initial request. `generate:books` writes the full, common index to `data/search-library.json`, with shared profile records and no duplicated normalised strings. First search fetches wire schema 2 lazily, checks installed book versions, record identities and filter metadata, and sends searchable projections and compact filter values to a module worker for normalisation/ranking. The same matcher provides a synchronous fallback when workers are unsupported or fail. Request IDs and controller generations prevent stale replies from replacing newer queries. It also generates `data/rule-reference-library.json` for validated source-text hydration. All dependency-context assembly happens at build time, not browser startup or first search. Shared core text and category controls do not import GM runtime into PC startup. Search shows loading/error feedback and a Retry control; stale/mismatched text is rejected rather than silently mixed with an older catalogue. Source/metadata/full-library outputs are all cached by the versioned offline worker, so first search also works after a completed offline installation.

## References and chaining

Adaptation/conversion notes and internal app decisions are **excluded from matching**. Explicit book-content fields are indexed instead of serialised records. `book-search-text.mjs` separates reviewed embedded annotations without deleting stored text, and preserves genuine book words such as “creator”. New imports must keep commentary in separate metadata. The app's approved adapted profiles remain searchable; original Fourth Edition reconstruction was not requested. Actual adaptations keep selective Legacy badges/explanations. Core source rules remain unchanged references even when the creator uses a user-approved convention, such as ignoring coin weight.

The reading pane contains book references, descriptions, profile fields and source/Legacy access, with no **Use in the creator** section, ownership/status panel or appended creator commentary. The reference workspace has no creator navigation or actions. Reading a book does not enable it or modify either draft. Actual creation controls remain authoritative.

Exact catalogue names and reviewed scoped aliases in the body become discreet links, preserving wording, word boundaries and the longest complete term. The current reference's own name and unimported terms stay plain. Same-book targets are preferred; multiple remaining targets require an explicit reference choice. Hover/focus provides a short desktop preview, click/tap opens the entry, and **Back / Previous reference** retraces the chain, including ambiguous choices. Separate source/Legacy dialogs can open above a reference in either creator and return to it. Chaining never changes a build or enables a book.

## Modules and maintenance

- `book-search.mjs`: creator-derived index and existing PC navigation context; re-exports the shared matcher.
- `search-ranking.mjs`, `search-engine.mjs`, `search-worker.mjs`: shared pure matching, lazy worker orchestration and worker/fallback ranking.
- `reference-entries.mjs`: strict independent schema for printed gameplay records; no creator mechanics.
- `scripts/search-coverage.mjs`: generated search inventory, source/output hashes and reference target checks.
- `rule-references.mjs`: source validation and lazy version/identity-checked hydration.
- `search-controller.mjs`: shared modal, persistent field, native filters, chips, loading/retry, keyboard, result batches, reader layout and return position.
- `search-filters.mjs`: category grouping, exact filter vocabulary, matching, options and wire validation.
- `search-metadata.mjs`: build-time source-field projection and reviewed identity-based classifications; never character state.
- `search-presentation.mjs`: shared category labels, escaped paragraphs/bullets/tables, Species metadata and related-term DOM links.
- `book-search-text.mjs` / `book-search-links.mjs`: annotation separation and exact related-name/alias resolution.
- `search-library.mjs`: build-time all-pack index, compact wire format and version-checked lazy loading.
- `reference-search.mjs` / `reference-body.mjs`: common source/Legacy reader, safe profiles and chain history.
- `features/book-search.mjs` / `gm/references.mjs`: thin entry-point wrappers around the same reader.
- `book-search.css`: shared desktop/mobile surfaces using Black Banner semantic tokens.

## Reviewed extraction workflow

Reuse MarkItDown text as the prose locator. The companion PDF-layout tools require PyMuPDF (reviewed with 1.28.2). `python scripts/extract-search-sources.py --book <book-id>` verifies the supplied PDF hash and stages coordinates/fonts outside the app. `python scripts/prepare-search-references.py --book <book-id>` proposes gameplay sections from the reviewed range recipe. After staging all supplements, `python scripts/prepare-search-profiles.py` proposes isolated stat blocks and flags nonstandard layouts. The default staging directory is the outer workspace's `tmp/pdfs/search-review`; the configurable tools refuse a directory inside `dist`.

These are review aids, not a reproducible one-command publisher. Check column order, table headers/continuations, labels, original numeric modifiers, printed-page offsets and profile rows against the PDF. Consolidate multi-page tables; give extracted examples an explicit context. Decide whether each candidate is included, already represented, consolidated, excluded or unresolved. Register only reviewed text in `reference-entries.json`, then freeze source/output hashes and target identities in `scripts/search-reference-review.json`. Excluded full text, raw layout and original PDFs remain outside the release. The creator rebuild helper preserves separately reviewed references, coverage and the installed version.

Table excerpts omit layout syntax while retaining printed values and footnote markers. The retained NPC source records are validated independently of the active search index and are not available through the shared reader. Related-term matching preserves hyphenated/apostrophe word boundaries, so “ill-fortune” does not silently link to Fortune.
