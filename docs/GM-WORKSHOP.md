# Bestiary Workshop

**Loot placement and flow (22 October 2026):** Equipment & magic has a Loot section immediately after Trappings and before Magic & knowledge. Its compact **Roll loot** action opens the existing native dialog style. Choose **Carried loot** or **Lair loot** and **1, 2 or 3 rolls**, inspect the result, then choose **Add loot** or **Reroll**; Close/Escape discards the preview. A closed-by-default **View d100 loot table** disclosure shows the complete original app table. People of the Reikland and explicitly identified supported humanoid Species default to Carried; other profiles conservatively default to Lair, with both choices always available. There is no inferred treasure tier or connection to combat strength.

The approved table is authored once in `src/engine/gm/loot.mjs` as `additional-loot-v1`. It uses exact existing core catalogue IDs and the user-approved coin/item/bundle quantities, not copied item rules or new values. An initial 00 generates two extra results; 00 on an extra result is rerolled rather than multiplied. Cryptographic rejection-sampled dice record all faces, quantities, times and app-table provenance, including discarded previews. A bounded pathological reroll sequence leaves no partial reward and retains its dice. Audit records appear in Customise → Characteristics → Recorded dice without a fabricated book/page citation.

Accepted loot uses a separate additive schema-2 `loot` array, with stable keys, `carried`/`lair` location, positive integer quantity and either exact item ID or brass/silver/gold denomination. Older saves missing it default to an empty array; explicitly malformed arrays/rows fail validation. Matching item/coin rows merge only within the same location; existing equipment stays separate. Quantities are editable (1–9999), locations are editable inside each row's disclosure, and entries are removable. Add, edit, remove, autosave, JSON, Undo/Redo and temporary print batches preserve the loot. Undo never erases rolled dice. A preview cannot be added twice or applied after its creature changes. Loot remains unequipped and cannot change attacks, AP, sizing requirements or other mechanics. Stat blocks/folio and both PDF formats include location-labelled loot and coins under **Gear**, using the shared Gear formatter. No key destination, map contents, jewellery value or magical property is invented.

Each selected Trait and Talent has a compact **Description** switch in Customise (Traits or Skills & Talents). It is visible outside the disclosure, beside rank/Remove controls, and has no On/Off text. The track stays 30 × 18px inside a 44px-tall tappable label; controls wrap beneath long names on narrow screens. All printed, added, template and training/trait-granted entries default to descriptions shown. Disabling the switch leaves the complete name, rating/parameter and Talent rank in the stat block, full PDF and A4 cards. The editor and general search retain the canonical rule and calculations continue unchanged.

Output preferences are saved as `hiddenDescriptions` in each GM draft, including autosaves, editable JSON and print-batch snapshots, with normal Undo/Redo. Existing schema-2 saves missing this additive field receive an empty list without mutating the imported object; explicitly malformed values still fail validation. GM row identities retain choices across parameter/name/rank edits. Template Talent identities include their template and selected name so replacement choices default to shown. The shared `ability-presentation.mjs` formatter supplies text and mixed-weight runs for preview, PDF and measured card drawing; hidden text does not occupy card height or leave a colon/blank description row.

## Source decisions and calculations

- Individual variation (p. 318): printed Characteristic −10 + recorded 2d10; rerolls replace the previous base value. Movement is not rolled. Dice use the shared cryptographic rejection-sampling function. Save files contain imported history, not independently verified randomness.
- Templates (pp. 353–354): one template applies to the baseline, except the explicit Tribes and Tribulations Troll composition (one type plus up to four modifiers). Alternative Skill slots need distinct choices. The user approved using the higher of the printed Skill bonus and template bonus; the app explains this interpretation and the worked-example discrepancies. Explicit GM Skill totals override the result.
- Size (pp. 360–361): each step changes S/T by 10 and Ag by −5. Five defined Wounds formulae are automated; Tiny needs a manual value. Only primary melee Damage receives the Size bonus. Printed profiles already include their bonuses.
- Giant Spider (p. 361): Small → Large gives S35/T45/Ag25, W26, Fangs +8 and Bite +6. The user chose the general Size rule over the worked example's Fangs +5. The conflict is shown in source notes.
- Orc (p. 337): retain printed T30/TB4. Once changing its calculations, require an explicit printed/calculated/manual Toughness Bonus decision. Other reviewed profile conflicts remain in their source notes.
- Dragon (p. 330): the user approved linking printed **Tracking 70** to **Track** for recalculation, retaining the naming mismatch in its source note. This is a scoped spelling correction, not a Legacy conversion.
- Venom (p. 363): the full Trait definition wins over conflicting short profile summaries. Wounds cause Poisoned; the Difficulty applies to recovery.
- Ogre (p. 324): Belligerent, Infected and Tracker appear under a printed Trappings heading; the user approved presenting them as suggested optional Traits.
- Trained (p. 363): Broken adds a recorded 2d10 to Fellowship, starting at zero if the printed value is absent; War adds WS10; Guard grants Territorial. Other training effects are references for play.
- Construct substitutes SB for WP Bonus in Wounds and has absent Int/WP/Fel when newly added. Swarm gains WS10, uses five times the normal creature's Wounds and ignores chosen Size adjustments; the normal creature's underlying profile remains the baseline. Hardy adds TB before the applicable Wounds multiplier.
- Explicit permanent Talent benefits and numeric Corruption table adjustments feed the calculated result. Other printed effects remain visible references; the GM can make an explicit score/Trait adjustment rather than the app inventing a value. Mark of Tzeentch requires a recorded count and alternating Mental/Physical choices. Corruption rolls use pp. 189–190.
- Quick Armour replaces detailed armour; shields remain conditional. Listed natural protection remains separate. Printed optional armour is never equipped without selection. Weapon quantity records ownership, not extra attacks.
- Source spelling/table corrections and documented Fifth Edition core ambiguities do not receive Legacy simply because the user chose an interpretation. Up in Arms mounts have selective Legacy metadata for the actual Size Damage and Stride conversions; unchanged printed scores are not separately tagged.
