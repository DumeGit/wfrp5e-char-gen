# Marijan Mode

A separate, unrestricted one-page character editor at `dist/marijan.html`. The user authorised this mode on 9 October 2026, using Hammergen as an interaction reference, not a rules source or copied interface. The guided player creator and GM workshop remain independent.

## Editing and calculations

Identity, all ten Characteristics, resources, Skills, Talents, magic/prayers, equipment, extras and notes are on one page. Collections and notes use native collapsible sections with stable disclosure keys; the section menu opens a collapsed destination. The creator-mode switch lives inside the shared bordered desktop `.rail`; on phones it moves into the same top-right banner menu as Player and GM, alongside Save/Load/New/Copy/Install. Undo/Redo and Export remain beside the editor. The phone folio opens from the single bottom View character action; Back to editor returns to the previous position. Desktop fields use compact 32px controls and calculated resources use short rows. Characteristics show a five-column Starting/Total grid (two columns on phones), with all Advances/Other fields in one native expandable editor. Selected Skills, Talents and equipment use compact ledger rows: name plus Advances/Total, ranks or quantity. An accessible chevron reveals source text, descriptions, Skill Characteristic/Auto–Manual controls and equipment location/profile overrides; selective Legacy badges stay visible beside the name. Mobile retains labelled 44px fields and 16px text, and stacks the existing parchment/leather components. The desktop summary stays beside the page; intermediate widths put it below.

There are no Career/Species restrictions, prerequisites, Talent rank limits, starting allocations, XP prices or money deductions. Career level and tracker boxes are independent entered values. Finite numeric values, including individual Advances and deliberate negative values, are accepted. Technical save-format checks still reject invalid objects, non-finite values and unsafe entry keys. Export does not require rule compliance or complete choices.

Characteristics are Starting + Advances + Other. The optional permanent Talent setting adds each printed +5 Characteristic benefit once and Fleet-footed's +1 Movement. Extra unrestricted ranks do not invent further benefits. Fate/Fortune and XP are entered independently; Luck never silently changes Fortune. A recorded crypto/rejection-sampled 2d10 roll replaces each Starting value with that Species modifier + dice sum, preserving Advances/Other; its die faces and timestamp are saved. Imported roll logs are not verified randomness.

Wounds reuse the shared core Size calculation; Hardy applies its printed benefit once. Tiny remains unknown without a manual value. Carrying capacity uses the existing Sturdy interpretation selector, Strong Back's first/two-rank effects and approved Ogre multiplier. The automatic equipment total is **listed unit Enc × quantity**, excluding stored items and coins; packing/worn reductions and load penalties are not applied. Armour sums recorded worn/equipped profiles by printed location, without enforcing layering restrictions. Unknown carried weights/AP stay unknown. Weapon Damage retains its entered printed expression or manual value. Traits, mutations, runes, Cants and other situational effects are recorded references, not automated effects.

Wounds, Movement, capacity, listed Enc, armour locations and Skill totals have explicit Auto/Manual controls. Manual values survive subsequent recalculation. Clearing a manual numeric field returns it to Auto. Switching Species or Career alone never deletes entries or grants equipment/abilities. **Species defaults** previews and explicitly applies Species Characteristic modifiers, Fate, Fortune, base Movement and Size; it preserves Advances, Other, entries and manual overrides, and grants no starting Skills/Talents.

## Random generation

The user approved higher-level generation by the Fifth Edition tracker method on 9 October 2026. **Generate character** opens a preview with a selected Species, an optional registered origin profile, a Species/origin-filtered printed Career and a target level 1–4. The ordinary Career browser and manual entry remain unrestricted. Custom Species/Career labels have no invented starting profile: enter their choices manually. Changing the generator's origin refreshes its eligible Career list; changing its controls invalidates any old preview. Applying replaces the draft, retaining its name, chosen Species/Career and free-text background. Undo restores the previous draft. No replacement happens when merely previewing or closing the dialog.

`marijan/generation.mjs` reuses `creationSpecies`, origin/Career availability, Specialisation options, native languages, random Talent tables, Skill/Talent eligibility, Trapping resolution, shared spell grants and the existing XP quote/purchase model. Actual dice use the shared rejection-sampled crypto helper. Selection rolls record their die size, faces, result label, timestamp and printed source; random allocation is explicitly an **app policy**, not a printed random-generation rule. Duplicate or incompatible random Species Talents are rerolled and documented. No Fourth Edition Fate/Resilience, six-at-+5/+3 Skill allocations, escalating Talent prices or eight-Skill completion thresholds are imported.

Starting generation rolls ten ordered 2d10 Characteristics with Species modifiers and randomly distributes the core's six accepted-first-roll points among level-one Career Characteristics (p. 38). It selects five distinct Species Skills at +5, native languages at +30, eight Career Skill Advances (+40 total) with the combined creation cap of +15, the Species Talent slots/random Talents and one valid Career Talent. Free spell/prayer grants use the existing acquisition-time counts and cult definitions. Basic Clothing/Dagger/Pouch, Class equipment and first-level Career Trappings follow core p. 39; rolled quantities, equipment aliases and unresolved weights/quantities reuse the inventory resolver. Starting wealth uses first-level Status/Standing (p. 39). Species and Career are selected, so there are no random Species XP or random Career Trapping/tracker rewards. Names, ambitions and optional ancestry/astrology/Longbeard choices are not invented or automatically completed.

Higher targets purchase valid in-Career +5 Characteristic/Skill Advances or Talents until the current tracker segment is full: 10 boxes, then 12, then 14. Choose equally among **available purchase groups**, then equally among valid purchases within the chosen group. Shared quotations enforce current-level eligibility, printed XP bands, Talent purchase limits and prerequisites. Each promotion costs 100 XP (p. 196); generation stops immediately upon entering the requested level. There is no arbitrary extra allotment at that level, automatic higher-level equipment, simulated downtime, or mandatory Fourth Edition Characteristic/Skill threshold. XP spent is the sum of the actual generation purchases; unspent is zero, editable afterwards.

The generated draft retains an **original generation record** with allocation policy, purchase prices and source-based reminders. This record does not change when freehand values are subsequently edited, and is included in JSON/PDF. Guided creator issues remain visible reminders in the preview/record, never Marijan export gates. Generated Skill totals/resources return to Auto, with existing permanent bonuses counted once.

**Add Species Skills**, **Add Species Talents** and **Add starting equipment** roll and add their respective choices without clearing other entries. Duplicate names use the higher existing/granted value rather than stacking grants on repeat clicks. Species Skills includes native languages; Species Talents includes their free spell/prayer grants. Starting equipment includes first-level Career equipment as well as the Class/basic items. These buttons do not roll wealth or spend XP. Their random records and changes are undoable. Separate additions may deliberately produce an unrestricted draft and do not claim a legal allocation history.

## Content and references

`marijan/catalogue.mjs` assembles all integrated non-variant PC packs once, expands their existing Skill/Talent choices and reuses `spellChoices`, Cants, techniques, runes, equipment and the reviewed GM Trait/mutation options. Explicit variant Career records are included separately without repeatedly assembling the entire library. No PDF extraction or separate authored equipment list is introduced. Existing same-name precedence and withdrawn profiles follow the shared catalogue. Inline name search and Book selectors narrow browsing only; no selected-book gate limits this mode. Exact/prefix name matches lead, and results expand in small batches. Search fields and source filters never enter saves.

Known entries retain their source and selective Legacy metadata. Species/Career references also expose their approved adaptations. Entry details allow character-local description/profile overrides. Shared all-book search remains reference-only and unchanged. Custom Skills, Talents, spells/prayers, Cants, weapons, armour, Trappings, Traits, mutations, runes and techniques have user-defined names/text and no invented printed source or automatic effects.

## Saves, copying and export

Schema 1 has type `wfrp-marijan`; `marijan/model.mjs` validates its structural shape independently of creator legality. Selected entries contain reference snapshots and character-local values. Local autosave uses `wfrp-marijan-v1`; named saves use `wfrp-marijan-v1-saves`. Isolated `?verify=1` storage appends `-verification`, including for copy-source selection. Local storage failures advise/use JSON backup instead. Save character updates its named local entry and downloads a JSON backup. Load can import JSON or choose a local named save. Wrong-tool save files are rejected. Undo/Redo covers edits, additions, removals, defaults, loads, copying and New character; text/number input edits are grouped rather than redrawn on each keystroke.

Copy player character accepts this device's player draft or a current player JSON. It calculates the existing player snapshot through `catalogForCharacter` and `characterResult`, then creates a **new** Marijan draft without writing to the original. Existing Characteristic bonuses are included with automatic Characteristic/Movement Talent effects disabled, Skill totals and derived fields retained as manual snapshots, and copied equipment kept at its resolved unit values. The original creation/XP history is not manufactured as unrestricted purchase records. There is no conversion back to legal guided creation.

PDF uses the supplied editable character-sheet template and local pdf-lib. All entered values, ranks, overrides, sources, custom descriptions, extra entries, notes and dice logs appear in a paginated appended Marijan record. Sheet space limits abbreviate or redirect to that complete record instead of silently dropping content. The record explicitly identifies unrestricted/manual creation and does not claim verified XP history. The exact entered tracker and Corruption values remain in the record even if the supplied sheet has fewer boxes. The JSON backup preserves all character data.

## Shared components and checks

Primitive `esc`, `score`, `button`, `field` and `select` controls are in `dist/controls.mjs`; GM controls re-export them. Wounds live in `dist/creature-calculations.mjs`, re-exported by the GM model. Mixed-weight PDF wrapping/drawing is in `dist/pdf-text.mjs`, re-exported by the GM helper. All tools share `creatorSwitch`, design tokens/skin, headings/emblem, disclosure capture/restore, reference search, install control and PWA runtime. Marijan-specific CSS owns layout and its banner image/crop; colours use the central Ash & Vellum theme of the shared Black Banner system. Its modules load only from its entry point; PDF export and player-copy calculations load on demand.

Focused checks: `node --test tests/marijan.test.mjs tests/marijan-generation.test.mjs` and `npm run test:ui:marijan`. Local Playwright covers desktop/mobile editing, inline additions, overrides, Undo, saving/reloading, actual PDFs and copying without changing the player draft. Shared component or release changes follow `docs/TESTING.md`. No GitHub tests or deployment actions are added.

Initial verification (9 October 2026): the release check passed 404 Node tests and 86 desktop/mobile browser cases; final focused checks passed 10 Marijan Node tests and 10 browser cases after the last refinements. The supplied editable sheet and appended record were rendered and visually checked, alongside desktop/mobile editor screenshots. No push or deployment was performed.

Compact layout/generation verification: 15 targeted Node tests and 14 desktop/mobile Marijan Playwright cases passed, with quick checks and offline asset validation. Desktop/phone layouts and generated editable sheet/record pages were visually inspected. Unchanged player/GM release suites were not repeated.

Compact-entry search keeps the query, Book and custom-entry action on one phone row. Leaving a search for an editor control hides results only once the click has reached its target, preventing layout movement between pointerdown and click. No rule values or save formats change.
